# 从主线找到真正需要修改的地方

先读引言的问题、方法的关键改变、主结果和结论。按材料填 [主张—证据表](../templates/claim_evidence.md)，不要先被修辞和统计表的外观影响判断。

## 四个连接

1. **问题 → 后果**：在哪种条件下发生什么困难，为什么现有处理不够？领域重要性只提供背景。
2. **困难 → 设计**：机制改变哪个决策或约束，为什么可能针对该困难？模块名字不能代替解释。
3. **设计 → 可检验主张**：区分性能、机制、效率、泛化与适用边界；总性能结果不能证明所有主张。
4. **主张 → 证据**：对应到数据、对照或推导；缺材料时写缺口，不自行补全。

理论、数据集、复现和负结果也可以是贡献，不强制写成“新模块提高性能”。

## 重组实验

每个实验说明“要区分哪两种解释、观察到什么、改变了什么判断”。按功能安排主结果、机制验证、适用范围和必要诊断。不设实验数量配额，也不要求所有模块都有单独消融，只要求实际提出的归因主张有对应证据。

大部分实验不确定时，核对研究问题、样本量、噪声和比较设计。能排除某种解释的负结果仍有信息；重复的无法判断的探索应合并说明并保留完整记录。核心反证不能藏进附录。

## 最小修改优先

论证缺口需要补证据或缩窄主张，表达缺口可以通过改写、合并和移动解决。不要用气势更强的语言掩盖未完成研究，也不要为局部编辑要求作者重做整篇实验。
